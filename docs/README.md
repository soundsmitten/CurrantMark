# CurrantMark documentation

This directory is the project record. Keep it current as the code changes.

## Start here

- [Architecture](architecture.md): current components, data flow, ownership,
  and extension seams.
- [Implementation status](implementation-status.md): what works, what is
  partial, and what is intentionally deferred.
- [Style guide](style-guide.md): the project’s Kodeco/Airbnb-inspired Swift
  conventions.
- [Contributing](contributing.md): the focused workflow for changes and
  handoffs.
- [Product scope](product-scope.md): current goals and explicit non-goals.

## Decisions

Durable choices live in [decisions/](decisions/). Add a numbered Markdown ADR
when a change affects architecture, dependencies, persistence, security,
packaging, or another decision future contributors would otherwise have to
rediscover.

## Documentation rule

Prefer updating the smallest existing document over creating a new document.
Create a new document only when it represents a distinct topic or decision.
Documentation should describe the repository as it is, label proposals as
proposals, and include validation boundaries where they matter.
